## Подтверждённые исходные проблемы

1. 03-configure-domain-workstation.yml использует плоский список roles;
   независимые компоненты не изолированы.
2. Публичный result.json записывает только domain_verify в конце исполнения.
   Частичный результат при ранней ошибке не сохраняется.
3. ConfigurePlanner.start() читает результат только при коде Ansible 0; при
   другом коде возвращает в основном domain_join_failed.
4. prejoin_upgrade помечает apt-get -y dist-upgrade изменившим систему без
   проверки реальной транзакции.
5. workstation_network записывает resolver без резервной копии, проверки
   результата и rollback.
6. Повторы для transient DNS/NTP/SSSD/GPO/LDAP и пакетных операций пока не
   имеют общего ограниченного контракта.

## Проверочная среда

ALT-тесты требуют POSIX-модулей аккаунтов и не исполняются в Windows Codex.
Их выполнение, Ansible syntax-check и интеграционные проверки проводятся в
изолированной Linux worktree контроллера или CI. Локальный Windows запуск не
считается доказательством работоспособности Ansible.

## Решение

Сначала принимаются PR-0 и PR-1: этот baseline, версия контракта результата,
матрица ошибок и RED-тесты. Изменение поведения контроллера, playbook 03,
DNS, package-management или AD join допускается только после того, как
соответствующий тест сначала воспроизводит проблему.

## Временный операторский запуск

До завершения managed ISO используется только controller-served launcher:

    curl --noproxy '*' -fsS http://192.168.100.17:8087/bootstrap/start-bootstrap.sh -o /tmp/start-alt-bootstrap.sh && sudo bash /tmp/start-alt-bootstrap.sh

Launcher не содержит учётных данных, скачивает канонический bootstrap во
временную root-only директорию, syntax-check выполняет до запуска и удаляет
временный файл при выходе.
