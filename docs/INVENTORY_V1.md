# Мобильная инвентаризация оборудования v1

## Назначение

`/inventory` — отдельная авторизованная мобильная страница для обхода помещений. Она ведёт локации, оборудование, фотографические доказательства, историю сетевых наблюдений и результаты обхода. Это модуль `web_ovpn`; Endpoint Platform в нём не используется.

## Данные и связи

- Локация имеет название и общий комментарий.
- Оборудование хранится отдельно от деталей конкретного типа. Поддерживаются: ПК, монитор, МФУ/принтер, телефон, ИБП и другое.
- ПК может иметь только один уровень связанных устройств. Одна дочерняя единица может быть активной только в одной связи; завершение связи не удаляет оборудование.
- Для оборудования отдельно сохраняются текущие IP, MAC и hostname, а старые значения остаются в истории с признаком `is_current=false`.
- Фотографии находятся в выделенном хранилище вне публичной раздачи. База содержит лишь относительный путь и метаданные.
- Сеанс обхода содержит подтверждения оборудования; подтверждение обновляет `last_verified_at`.

## Мобильный поток

Работа с инвентаризацией идёт последовательно: **список локаций → дерево выбранной локации → карточка одного устройства**.

1. Откройте `/inventory`. Страница показывает только список локаций; создайте новую локацию или откройте существующую.
2. На странице локации просмотрите дерево: ПК и связанные с ним устройства отображаются вместе, а самостоятельные устройства находятся на верхнем уровне. Здесь же можно изменить название или комментарий локации.
3. Добавьте самостоятельное устройство кнопкой `+ ДОБАВИТЬ УСТРОЙСТВО`. Чтобы добавить связанное устройство, используйте `+ ДОБАВИТЬ СВЯЗАННОЕ УСТРОЙСТВО` рядом с нужным ПК в дереве.
4. Создание, поиск в сети, ручное заполнение и редактирование открывают карточку только одного устройства. Для связанного устройства родительский ПК в форме не показывается: связь передаётся и проверяется сервером. После сохранения вернитесь к дереву этой же локации.
5. При создании ПК или телефона, до открытия карточки устройства, введите IP, MAC или hostname и нажмите `НАЙТИ УСТРОЙСТВО`. Результат netctl/nmap автоматически предзаполняет поля будущей карточки; оператор проверяет, при необходимости изменяет их и сохраняет устройство.
6. При необходимости прикрепите снимки камеры на сохранённой карточке конкретного устройства. Фотографии принадлежат этому устройству, а не связи или локации. Принимаются файлы с корректной сигнатурой JPEG, PNG или WEBP, даже если мобильный браузер передал пустой либо неточный `Content-Type`.

## Сетевой поиск и безопасность

- Для MAC выполняется поиск по текущему netctl-снимку; при отсутствии — один контролируемый refresh и повторный поиск.
- Для одиночного IPv4 при отсутствии netctl-результата разрешён только bounded-вызов `netctl fingerprint inspect-ip --target <IPv4>`.
- CIDR, диапазоны, произвольные профили nmap, hostname-to-nmap и shell-команды не принимаются.
- Любой результат поиска создаёт `inventory_observations` и запись аудита; предложения не меняют карточку автоматически.
- Все записи API требуют Bearer-токен и CSRF-токен связанной авторизованной сессии. HTML-формы требуют CSRF. Доступ к фотографиям также требует авторизации.

## Настройки

- `INVENTORY_PHOTO_ROOT` — корень фотографий, по умолчанию `/var/lib/openvpn-web/inventory-photos`.
- `INVENTORY_PHOTO_MAX_BYTES` — максимальный размер одного файла, по умолчанию `10485760`.

Каталог фотографий должен быть доступен на запись процессу веб-приложения и не должен быть опубликован веб-сервером как статический каталог.

## API v1

Префикс: `/api/v1/inventory`.

- Локации: `GET/POST /locations`, `GET/PATCH /locations/{id}`, `GET /locations/{id}/tree`.
- Оборудование: `GET/POST /assets`, `GET/PATCH/DELETE /assets/{id}`.
- Рабочее место: `POST /workplaces`; связи: `POST /relations`, `DELETE /relations/{id}`.
- Поиск: `POST /lookup`, опционально с `asset_id` для привязки наблюдения.
- Обход: `POST /sessions`, `POST /sessions/{id}/checks`, `POST /sessions/{id}/finish`.
- Фотографии: `POST /assets/{id}/photos`, `GET/DELETE /photos/{id}`.

Все изменяющие API-методы используют заголовок `X-CSRF-Token` совместно с `Authorization: Bearer …` и авторизованной браузерной сессией.
