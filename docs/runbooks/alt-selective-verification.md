# Выборочная проверка выпуска ALT

На ALT установщик контроллера сам выбирает тесты. Ручного списка компонентов
для допуска к выпуску нет. Подготовьте root-owned неизменяемый комплект,
проверенную резервную копию с пробным восстановлением и актуальный
maintenance-review. Действующие задания и UNKNOWN обрабатываются прежними
штатными процедурами.

## Посмотреть решение

```sh
release_source=/opt/alt-deploy-source-<revision>
sudo python3 -I "$release_source/deploy/alt-linux/verification_checkpoint.py" \
  --source "$release_source" --cache /var/cache/alt-deploy-install-verification \
  --python /usr/bin/python3 --plan
```

Команда показывает `mode`, `reason`, непосредственно изменённые `components`,
затронутые связями `affected`, пути и точные `targets`. Она не запускает тесты,
не создаёт квитанций/базу и не разрешает rollout. Решение заново вычисляется под
блокировкой при настоящей проверке.

## Обычный выпуск

```sh
sudo bash "$release_source/deploy/alt-linux/install-control-plane.sh" \
  --rollback-backup-id backup-YYYYMMDDTHHMMSSZ-xxxxxxxx \
  --maintenance-review <CURRENT_REVIEW_SHA256>
```

- Известная изолированная роль и её описанные тесты: вся группа компонента,
  проверки затронутых потребителей и обязательные общие контракты.
- Браузер, CryptoPro, CAdES и ГосПлагин проверяются вместе; учитываются связи
  с Directum и ярлыками. Есть отдельные области ONLYOFFICE, Nextcloud, Directum,
  VK WorkSpace, gpupdate compatibility, desktop/KWallet и KRFB.
- Общий controller/installer/backup/очередь/авторизация, общий каталог/профили,
  окружение Python/RPM, правила выбора тестов, общие fixtures, неизвестные пути,
  удаление/переименование и смена прав требуют полного набора.
- Добавление помощника в `tasks/files/templates/defaults/vars` известной роли
  остаётся в её области. `meta`, handlers, Ansible plugins и новые межролевые
  include/import либо неоднозначный граф задач требуют полного набора.
  Новый тестовый
  файл сначала нужно зарегистрировать в карте: изменение карты проходит полный
  набор. Изменение уже описанного теста проверяется вместе с его компонентом.
- Для сопровождающих Markdown-инструкций разрешены только операторское
  руководство, эти runbooks и документы планов/спецификаций; неизвестные пути
  документации также требуют полной проверки.

Полный набор включает `tests/alt_linux` и внешние относительно этой папки
интеграционные тесты из карты. В обоих режимах проверяются зависимости, синтаксис
общих скриптов и всех Python-помощников ролей. Среда и UID одинаковы.

Принудительно выбрать полный набор можно параметром `--full-verification`.
Уменьшить набор флагами `--component`/`--skip-tests` нельзя.

## Подтверждённая база и продолжение

База — последний успешно проверенный снимок, а не произвольный Git commit или
состояние установленного ПК. Root-private cache хранит содержимое/режимы файлов
и каталогов,
отпечатки окружения и правил, точный объём тестов и происхождение от полного
прогона. Проверка одного компонента наследует только неизменённую проверенную
часть; следующий компонент сравнивается с последним подтверждённым снимком.

Первый выпуск нового механизма и отсутствие подходящей базы требуют полного
прогона. Старые schema1-квитанции не импортируются как новая база. База не
истекает только из-за времени: смена окружения/правил или общего кода требует
полного прогона независимо от возраста. Квитанция повторного использования
точного комплекта по-прежнему действует шесть часов.

После временного отказа до rollout используйте `--resume-verification` для
того же комплекта. Он принимает проверенный полный или выборочный результат.
Комбинация с `--full-verification` принимает только результат полного прогона.
Изменившийся комплект проверяется обычным запуском с новым автоматическим
решением. Не редактируйте и не подменяйте базу/квитанции вручную.

Неудачная новая правка не отменяет её неизменённую подтверждённую базу. Если
повторная проверка ранее подтверждённого снимка противоречит прежнему успеху,
его семейство подтверждений отзывается до нового полного прогона. Каждая новая
полная проверка имеет отдельный идентификатор даже при неизменившихся часах.
При наследовании проверяется вся цепочка снимков до полного прогона, включая
отзыв промежуточных результатов. Изменение используемого YAML-парсера также
отменяет пригодность старой базы.

Backup eligibility, активные задания, Vault, права, pending-registration,
rollout begin/authorize/readiness/complete остаются свежими и обязательными.
Снимок проверки не разрешает Setup/повтор UNKNOWN и не продолжает уже изменённый
частичный rollout: для этого используется штатное восстановление OR-3P3.
