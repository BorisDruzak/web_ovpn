# ALT: единая проверка и продолжение до начала rollout

## Тестирование

На ALT с Python 3.12 и подготовленными зависимостями используется одна команда:

```sh
bash deploy/alt-linux/run-tests.sh
# Тот же UID/окружение, но целевой набор для разработки:
bash deploy/alt-linux/run-tests.sh tests/alt_linux/test_prejoin_upgrade_compat.py
```

От root команда передаёт выполнение `altserver`; от другой учётной записи
проверка отказывает. Перед тестами проверяются зависимости и синтаксис. Прогон
последовательный, с umask022, чистым окружением, приватными короткими временными
путями и кэшем Python. Каталог исходников не используется как кэш. Целевой прогон
не создаёт квитанцию полного прогона для установщика.

## Установка контроллера

Используйте неизменяемый опубликованный комплект в root-owned каталоге без
групповой/общей записи, например `/opt/alt-deploy-source-<revision>`. Выполните
обычные backup/verify/rehearse и подтверждение текущего maintenance-review.

```sh
sudo bash deploy/alt-linux/install-control-plane.sh \
  --rollback-backup-id backup-YYYYMMDDTHHMMSSZ-xxxxxxxx \
  --maintenance-review <CURRENT_REVIEW_SHA256>
```

Перед дорогими тестами выполняются быстрые живые проверки; после них — повторные
свежие проверки. Успешный полный прогон сохраняет root-private квитанцию в
`/var/cache/alt-deploy-install-verification` (каталог0700, файлы0600). Она привязана
к содержимому/режимам исходников, тестам, версии/бинарнику Python, служебному UID,
RPM-составу, метаданным зависимостей и содержимому исполняемых Python import paths,
включая stdlib, `.venv`, незарегистрированные `.pth` и `sitecustomize.py`.
Изменение исходников или окружения,
небезопасные пути, повреждение и возраст более шести часов запрещают повторное
использование. Неудачный новый прогон аннулирует предыдущий результат для тех же
входных данных. Изменения во время тестов также запрещают сохранение квитанции.

Если **после успешного прогона, до начала rollout** временно пропала связь с ПК
либо не прошла живая проверка, восстановите причину, получите актуальный допуск
обслуживания при необходимости и выполните:

```sh
sudo bash deploy/alt-linux/install-control-plane.sh \
  --rollback-backup-id backup-YYYYMMDDTHHMMSSZ-xxxxxxxx \
  --maintenance-review <CURRENT_REVIEW_SHA256> \
  --resume-verification
```

Повторно используются только тесты. Backup eligibility, активные задания,
Vault, права, ключи, pending-registration, rollout begin/authorize/readiness/
complete проверяются штатно. Квитанция не является разрешением на запись.
При отсутствии/устаревании квитанции команда отказывает; новый обычный запуск
выполнит полный прогон. Автоматического обхода ошибок или отключения guards нет.

Если rollout уже начался и менял runtime, применяйте штатный разбор/восстановление
OR-3P3; этот флаг не продолжает частично изменённый rollout. Не редактируйте
квитанции, маркеры, планы, claims и историю UNKNOWN вручную.
