# Сетевые проверки UI VPN

В меню **Сеть и диагностика → Сетевые проверки** можно проверить маршрут ядра VPN-сервера, рассчитать прямой путь от сетевого актива по данным RouterOS, запустить трассировку до наблюдаемого IPv4-узла и проверить связь с включённым источником Network Observer. В истории запусков видны назначение, время и результат для текущего оператора.

| Проверка | Что означает результат |
|---|---|
| `linux_route` | Маршрут, выбранный ядром VPN-сервера для IP-адреса. Команда `ip route get` читает решение ядра без отправки пакетов. |
| `asset_route` | Расчёт прямого пути, таблицы маршрутизации и применимых правил по собранным фактам RouterOS. При неполных или устаревших фактах результат `unknown`. |
| `trace_route` | Переходы, ответившие на трассировку от VPN-сервера. Запуск разрешён для IPv4-адреса из мониторинга, максимум 12 переходов и 18 секунд. Промежуточный узел может пропустить запрос, сохраняя пересылку трафика. |
| `source_test` | Результат штатной проверки `netctl sources test` для включённого источника. |

## API и MCP

API использует Bearer-токен панели. Для чтения требуется `network:read`, для запуска проверки — `network:diagnose`.

| HTTP | MCP |
|---|---|
| `GET /api/v1/network/diagnostics/checks` | `openvpn_network_diagnostic_checks` |
| `POST /api/v1/network/diagnostics/checks` | `openvpn_network_run_check` |
| `GET /api/v1/network/diagnostics/runs?limit=20` | `openvpn_network_check_runs` |
| `GET /api/v1/network/diagnostics/interfaces?source=…&interface=…` | `openvpn_network_interface_history` |

Для запуска передайте JSON с идентификатором проверки и её параметрами.

```json
{"check": "linux_route", "destination": "192.0.2.20"}
```

`asset_route` дополнительно принимает `asset_key`, `protocol` и `port` для TCP или UDP. `source_test` принимает `source`. Детали проверки возвращаются в `data.result`, код результата — в `data.status`. История содержит итог каждого запуска и идентификатор запроса. При отсутствии установленного `ip` или `tracepath` соответствующая проверка возвращает `unavailable`.

Для активных проверок действует общий интервал повторного запуска по оператору и типу проверки. В течение пяти минут повтор вернёт `rate_limited`.
