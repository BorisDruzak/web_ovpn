# Приёмка сетевой диагностики

## Перед развёртыванием

- [x] Сверить изменения в `main`, состав развёрнутых файлов и очередность перезапусков с задачей Центра инфраструктуры.
- [x] Проверить версии iperf3 и dumpcap, маршрут от VPN-сервера до выбранной управляемой точки, адрес источника и ограничения слушателя.
- [x] Описать в операторском профиле источник захвата, IP и порт назначенного тестового потока. Проверить владельца и права файла конфигурации и каталога PCAP.

## Измерение пропускной способности

- [x] Запустить отправку и приём с одного и того же утверждённого сервера. Сверить скорости отправителя и получателя, длительность, целевой темп и результат при недоступности сервера.
- [x] Проверить, что IP, порт и параметры нагрузки берутся из профиля. Запросы с произвольным адресом или параметрами команды должны отклоняться.
- [x] Указать обе точки измерения. Отдельно записать, какой участок сети проверен и достиг ли поток целевого темпа.

## Захват для Wireshark

- [x] Запустить захват выбранного потока и создать известный трафик в течение окна записи. Проверить, что скачанный файл читается Wireshark или capinfos и содержит пакеты только выбранного IP, протокола и порта.
- [x] Проверить границы времени, числа пакетов и объёма. Пустой захват должен отличаться от ошибки выполнения.
- [x] Проверить владельца, право скачивания, срок доступа и очистку. Проверить, что другой оператор и токен без права диагностики не могут получить файл.

## Признаки L2-петли

- [x] На фикстурах проверить повторное перемещение MAC между двумя портами одного VLAN, одиночное перемещение, смену VLAN, устаревшие данные и недостаточную выборку.
- [x] Проверить, что сочетание повторного перемещения и события STP повышает уверенность. Отдельный сигнал должен оставаться наблюдением.
- [x] Прочитать реальные данные минимум одного коммутатора. Зафиксировать охват источников, свежесть и найденные признаки.

## UI, API и MCP

- [x] Проверить каталог, запуск и аудит во всех трёх интерфейсах. Для PCAP проверить скачивание через каждый интерфейс.
- [x] Проверить доступность новых операций в OpenAPI, работу установленного MCP-скрипта и браузерный сценарий на узком экране.
- [x] Сверить состояние панели и Network Observer после развёртывания. Зафиксировать коммиты, результаты проверок и границы наблюдения.

## Приёмка 12 ноября 2026 года

- VPN-сервер и управляемый узел LAN прошли замер в обоих направлениях. Скорость получателя составила 5,24 Мбит/с в каждом направлении при четырёхсекундном профиле с целевым темпом 5 Мбит/с. Точка отказала в соединении с проверенного адреса вне разрешённого списка. Вызов драйвера к неактивному локальному слушателю вернул `failed`.
- В живом PCAP 377 пакетов и 33 408 байт. `capinfos` распознал классический PCAP и длину снимка 96 байт. `tcpdump` не нашёл пакетов вне профиля. Файл, скачанный через API, совпал с локальной копией, созданной MCP. Авторизованный браузерный маршрут отдельно вернул живой PCAP и отказал в скачивании файла сервисного оператора. Срок доступа, очистку, ограничение объёма и отсутствие права скачивания проверили тестами.
- Реальный опрос охватил девять коммутаторов. На одном признаки петли отсутствовали в окне наблюдений, для восьми недостаточно данных. По всем восьми отсутствовали наблюдения STP. Положительную корреляцию, которая возвращает `suspected_loop`, проверили на фикстуре. Широковещательные счётчики в оценку не входят.
- 363 целевых теста прошли. В Playwright проверили запуск трёх форм и скачивание PCAP при ширине 390 пикселей. На развёрнутой панели проверили авторизованные HTTP-формы, скачивание, MCP, API и OpenAPI. Веб-служба и таймер Network Observer активны.
- Релиз содержит коммиты `985197a2` и `4b30ede2`.

### Открытые сценарии приёмки

- [ ] Проверить **от управляемого клиента OpenVPN** DNS и HTTP внутреннего сервиса. Для приёмки нужен подключённый пробник с подтверждённым путём через туннель.
- [ ] Подтвердить восстановление **ИС74** и **IPsec до архива** по плановым результатам. Для ИС74 сверить первый переход на внешних целях. Для IPsec сверить политику, SA и доступность в обе стороны.
- [ ] Выполнить отдельные замеры iperf3 по WAN и до архива, указать источник, приёмник и наблюдаемый путь. Нужны доступные управляемые слушатели. Замер внутри LAN проверен отдельно.
- [ ] Уточнить охват L2-диагностики. На момент сверки оценка по девяти источникам вернула `insufficient_data`. Для приёмки на нужном участке требуется окно со свежими наблюдениями MAC и STP, а для широковещательной нагрузки нужны счётчики соответствующих интерфейсов.
