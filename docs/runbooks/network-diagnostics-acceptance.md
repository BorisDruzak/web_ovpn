# Приёмка сетевой диагностики

Из корня репозитория запустите `python -m deploy.verify_network_diagnostics` с переменными подключения OpenVPN Control `OPENVPN_WEB_BASE_URL` и `OPENVPN_WEB_API_TOKEN_FILE` или `OPENVPN_WEB_API_TOKEN`. Для проверки установленной копии MCP добавьте `--mcp-script` с путём к её `openvpn_mcp_server.py`. Скрипт читает OpenAPI, сравнивает каталоги REST API и MCP, сверяет состав и свежесть плановых результатов и выводит статусы проб в JSON. Для каждого планового профиля `run_id` указывает проверенную запись, а `api_matches` показывает, совпала ли запись с тем же ID в REST API, включая результаты всех проб. `loop_diagnostics.source_coverage` содержит свежесть FDB и STP, число пригодных интервалов широковещательных счётчиков и признаки усечения по каждому коммутатору.

Код `0` означает, что контракты доступны и свежие плановые результаты совпали в REST API и MCP. Код `1` означает ошибку проверки, отсутствие свежего результата или расхождение результатов. С параметром `--require-reachable` код `2` означает, что один или несколько маршрутов с актуальными данными недоступны. Допустимый возраст результата по умолчанию составляет 10 минут и задаётся параметром `--max-age-minutes`.

### Открытые сценарии приёмки

- [ ] Проверить DNS и HTTP внутреннего сервиса **от управляемого клиента рабочего OpenVPN**. Для приёмки нужен подключённый пробник с подтверждённым путём через рабочий туннель.
- [ ] Подтвердить восстановление **ИС74** и **IPsec до архива** по плановым результатам. Для ИС74 сверить первый переход на внешних целях. Для IPsec сверить политику, SA и доступность в обе стороны.
- [ ] Сравнить скорость HTTPS по провайдерам и выполнить отдельные замеры iperf3 по WAN и до архива. Для каждого замера указать источник, приёмник и наблюдаемый путь. Нужны работающий маршрут ИС74 и доступные управляемые слушатели iperf3.
- [ ] Повторить пробу VLAN20 после восстановления прохождения VLAN до шлюза. Наблюдаемое расхождение на линии D-Link `Slot0/52` ↔ SNR `ge21` приведено выше.
- [ ] Подтвердить охват L2-диагностики за пределами SNR. У CSS326 есть STP и интервалы широковещания, нужен источник наблюдений MAC с VLAN. У TP-Link есть FDB и интервалы широковещания, у D-Link — FDB. Для этих трёх коммутаторов нужна история из источника с подтверждённым активным STP. У D-Link также нужен проверенный источник широковещательных счётчиков. У SNR для расчёта широковещания требуется маркер разрыва счётчиков.
