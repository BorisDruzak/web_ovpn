# Общая локальная проекция сети

`app.inventory.network_projection.attach_network_projection` используется в
первичной HTML-отрисовке `/network/hosts` и API `/api/v1/network/hosts`.
Привязка выводится из подтверждённой связи Netctl с активной физической
карточкой, затем из подтверждённой канонической связи этой карточки с Endpoint.
MAC-кандидат не становится подтверждённой связью агента. Несколько интерфейсов
карточки используют одного агента, без ослабления его уникальности.

Состояния: интеграция отключена, неизвестно, нет подтверждённой привязки,
кандидат, неоднозначность и подтверждённая связь. Свежесть хранится отдельно:
актуально, устарело, источник недоступен либо неизвестно. Успешное чтение
старого baseline не освежает его дату сбора: используется существующая
`endpoint_profile_freshness`. Для старых кешей без метаданных профилей
сохраняется оценка по общему времени успешного обновления.

Чтение выполняется пакетно из локальной БД для выбранной страницы.
GET не вызывает сбор, SDK или отдельные запросы к Endpoint на каждую строку.
API-токен без `inventory:read` получает состояния без данных карточки,
идентификаторов связей и устройства Endpoint.

`inventory_network_projection_version` — одно локальное число версии.
SQLite-триггеры увеличивают его в той же транзакции при изменении карточек,
локаций, связей Netctl/Endpoint, кеша состояния и управления источником.
Rollback откатывает и версию. Повторный `init_db` сохраняет версию и данные.
Внешний `projection_version` включает также настройку интеграции и 30-секундный
интервал оценки свежести. Metadata polling сравнивает его независимо от
Netctl `snapshot_id`; изменение локальной связи обновляет строки при прежнем
снимке. Старение кеша обнаруживается и без записи worker.

Это ещё не полный T13: поиск/создание/управление связями из обоих разделов,
подключение к worker, фильтрация всей выборки до пагинации и экспорт остаются
следующими этапами. Новый счётчик и его триггеры проверены для SQLite.
