# Complete Workstation Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in this chat. Steps use checkbox (`- [ ]`) syntax for tracking. The operator already selected native execution in this chat; do not ask them to choose an execution method again.

**Goal:** Deliver one complete web/MCP workstation preset with VK WorkSpace, automatically completed KRFB with direct password-authenticated VNC after real login, and verified final DNS, preserving historical jobs and legacy contracts.

**Architecture:** Extend the existing component registry and original Setup job with a strictly versioned three-phase workflow. Initial system execution retains the protected domain adapter; durable worker-owned user and final-DNS phases cannot invoke it. Target-owned direct VNC policy and backend-aware DNS use fixed published helpers, independent fresh evidence and existing lifecycle/queue locks.

**Tech Stack:** Python 3.12, existing PyYAML 6.0.2 and cryptography dependency, ansible-core 2.18.6 in CI, FastAPI/Jinja, existing browser JavaScript and Playwright MCP, ALT Workstation K 11.x with NetworkManager/Etcnet and nftables.

**Spec:** `docs/superpowers/specs/2026-10-20-complete-workstation-workflow-design.md`, approved by the operator on 2026-10-20. Baseline: `e93b95389a481a2446d22fe5e6c0f2279f1522d4`.

**Approval and amendments:** On 2026-10-20 the operator approved implementation in this chat, including direct TCP/5900 with mandatory KRFB password and a new first task for AD quota/effective rights admission plus complete safe error diagnostics. No new choice of execution method or intermediate permission loop is required; concrete native release SHA/TTL and separately scoped reboot gates remain.

## Global Constraints

- The ordinary web wizard offers one complete workstation set: `workstation-full-v1`.
- Preserve `base`, `core-apps`, `office-standard-v1` and `office-signature-v1` definitions, API compatibility and all archived requests/results.
- Component declarations, dependencies, role mapping and verification remain in the existing published registry.
- Keep ordinary status polling and existing verification read-only. A web view or verification click must not become the hidden executor.
- Do not change old UNKNOWN entries, replay old jobs, reset computer accounts or release consumed recovery claims.
- Do not create a synthetic home, use employee credentials for automatic login or share the greeter.
- Preserve the existing lifecycle lock, global single-PC execution and fair queue handling; waiting for human login must not block other eligible PCs.
- VNC accepts direct TCP/5900 connections with mandatory password authentication and no unauthenticated RFB mode. Remove only the proven owned SSH-only restriction and disable its startup service; preserve unrelated firewall policy. No global environment assertion substitutes for actual target evidence.
- Final DNS is the last mutating component. Preserve addressing, routes, DHCP options, connection ownership and unrelated user files; no network down, workstation reboot or infrastructure change is implicit.
- Keep secrets, private operational evidence and application/user data out of Git and public logs. The final resolver is populated in protected controller policy, then explicitly displayed in the concrete plan.
- Rehearse on an isolated clean ALT clone with a distinct identity and fresh snapshot; do not reinstall the current completed pilot.
- Wait for successful hosted CI for the exact release SHA; use fresh native maintenance coverage and backup/verify/rehearse before guarded deployment. Old expired SHA/TTL approvals are not reusable.
- Run meaningful RED/GREEN tests per task, review each complete diff and `git diff --check`, and commit only task files with Conventional Commit messages. No implementation is claimed by this planning document.

## Review Focus

1. A controller restarts after a phase claim but before a result/status publication: retain UNKNOWN and never execute that phase or join again (Task 5).
2. An old queue receipt expires while the employee is away: obtain fresh phase-bound technical admission without extending/editing the old receipt or admitting unrelated history (Tasks 4–5).
3. DNS is supplied by a read-only Etcnet backend or changes concurrently: use the actual owner and refuse to overwrite unowned changes; prove rollback or retain uncertainty (Task 3).
4. A same-named local account, fabricated home, wrong graphical user or stale boot appears ready: keep waiting or fail closed, with zero mutation (Tasks 2, 5).
5. A user already has a VNC client or application configuration: preserve that session/data; report a concrete wait instead of restarting the desktop or uninstalling software (Tasks 1–2).
