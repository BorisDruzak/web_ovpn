# Инвентаризация: поток от локации к устройству

## Цель

Заменить текущую смешанную страницу `/inventory` последовательным мобильным потоком:

1. список локаций;
2. выбранная локация с иерархией устройств;
3. отдельный экран создания либо редактирования одного устройства.

Оператор не должен выбирать локацию из выпадающего списка, видеть форму устройства рядом с деревом либо видеть карточку родительского ПК при создании и редактировании связанного устройства.

## Границы

- Существующие локации, устройства, связи, фотографии, сетевые наблюдения и API v1 сохраняются без миграции данных.
- Модель остаётся двухуровневой: ПК может быть родителем, связанное устройство находится ровно на одном уровне под ним. Самостоятельные устройства остаются верхнеуровневыми в локации.
- «Начать обход» и элементы управления сеансом обхода убираются только из HTML-потока. Исторические записи `inventory_sessions` и API не удаляются.
- Десктопная навигация и мобильное выдвижное меню не меняются.

## Экран 1: список локаций

`GET /inventory` отображает только карточки локаций, отсортированные по названию. Каждая карточка содержит название, краткий комментарий и ссылку на экран этой локации. Ни выпадающего списка, ни текущего дерева устройств, ни кнопки «Начать обход» здесь нет.

Под списком есть одна кнопка `+ ДОБАВИТЬ ЛОКАЦИЮ`, ведущая на отдельную форму `GET /inventory/locations/new`. После сохранения `POST /inventory/locations` перенаправляет на созданную локацию.

## Экран 2: выбранная локация

`GET /inventory/locations/{location_id}` показывает:

- кнопку `К СПИСКУ ЛОКАЦИЙ`;
- название и комментарий локации;
- кнопку `РЕДАКТИРОВАТЬ ЛОКАЦИЮ`, раскрывающую на этой же странице форму изменения названия и комментария;
- иерархию устройств;
- кнопку `+ ДОБАВИТЬ УСТРОЙСТВО`.

Дерево рендерится из существующего `location_tree`: для каждого ПК — ссылка на карточку и расположенная рядом кнопка `+ ДОБАВИТЬ СВЯЗАННОЕ УСТРОЙСТВО`; под ним — связанные устройства-ссылки. Самостоятельные устройства идут отдельными верхнеуровневыми карточками. Кнопка связи показывается только у типов, разрешённых сервисом быть родителем (сейчас ПК).

Создание самостоятельного устройства стартует с выбранной локацией в URL/скрытом поле. Связанный сценарий стартует из кнопки рядом с конкретным ПК. После создания либо сохранения карточки пользователь возвращается к дереву той же локации.

## Экран 3: устройство

Создание, сетевой поиск, ручное заполнение и редактирование остаются разными страницами одного устройства. Экран содержит только редактируемое/создаваемое устройство и контекст локации; родительская карточка ПК и её раскрывающийся блок не показываются.

Для связи открывается отдельный выбор типа. После выбора открывается полная форма нового дочернего устройства. Родитель не визуализируется, но его идентификатор передаётся серверу и валидируется; связь сохраняется только если обе записи принадлежат одной локации.

Сетевой поиск сохраняет действующее правило: для ПК и телефона сначала поиск по IP/MAC/hostname; для связанного монитора, принтера, ИБП и другого оборудования доступен ручной ввод. Все ссылки возврата ведут на локацию, а не на старый общий экран.

## Фото

Блок фотографии остаётся только на сохранённой карточке конкретного устройства. Каждая загруженная фотография читается по записи этого устройства, а не по связи или локации.

Сервер проверяет фактическую сигнатуру JPEG, PNG или WEBP и сохраняет определённый по содержимому MIME-тип. Значение `Content-Type`, пришедшее от мобильного браузера, не должно отклонять корректный файл с известной сигнатурой: камеры часто отправляют неполный либо неточный MIME. Лимит размера и запрет неизвестных форматов сохраняются. Ошибка загрузки возвращается оператору как понятное сообщение без потери заполненной карточки.

## Маршруты и совместимость

Новые HTML-маршруты добавляются рядом со старыми:

- `GET /inventory/locations/new` — форма новой локации;
- `GET /inventory/locations/{location_id}` — дерево и inline-редактирование локации;
- `POST /inventory/locations/{location_id}` — изменение названия и комментария.

Старый `POST /inventory/location/select` сохраняется как совместимый переход, но больше не используется интерфейсом. Непараметризованные старые ссылки создания устройства продолжают безопасно использовать выбранную в сессии локацию либо перенаправляют в список, если локации нет. API v1 не меняется.

## Проверка

Автоматические тесты покрывают:

- пустой и заполненный список локаций, переход в выбранную локацию и создание новой;
- изменение названия и комментария на экране локации;
- дерево ПК → связанные устройства, самостоятельные устройства и кнопку добавления связи рядом с ПК;
- отсутствие родительской карточки на форме создания и редактирования связанного устройства;
- возврат после создания/редактирования к нужной локации;
- загрузку PNG, JPEG и WEBP, включая корректный файл с неверным `Content-Type`, и отказ неизвестного либо слишком большого файла.

Перед развёртыванием выполняется `pytest tests/test_inventory_web.py -q`, затем браузерная проверка на мобильной ширине: список локаций, дерево, создание связи, сохранение устройства и фото.
